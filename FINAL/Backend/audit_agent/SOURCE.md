## What was vendored

Only the runtime pieces needed by BSS:

- `bss_agent/`
- `config/`
- `assets/`
- `Agent1_AuditableFields_v3.xlsx`
- `run_agent.py`
- `VERSION`
- `requirements*.txt`

## What was deliberately excluded

- `samples/` — contains worker PII
- `design/` — sample PDF/HTML design files
- `webapp/` — the standalone admin console; BSS has its own UI
- `tools/`, `tests/`, `deploy/` — original packaging/deployment files

## BSS modifications

- `bss_workers.json` overlay: the BSS bound-worker master becomes the ground truth for identity/employment comparisons.
- New checks: submitted worker not bound to the contractor/site/month; UAN/ESIC/DOJ/designation compared with the BSS master.
- `DEEPSEEK_BASE_URL`, `DEEPSEEK_MODEL`, `DEEPSEEK_CACHE_DIR` environment support.
- The report is generated by the isolated runner; BSS only stores/serves it.

The original `.sha256` is verified before extraction. Do not commit the original tarball.
