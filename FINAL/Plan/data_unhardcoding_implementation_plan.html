Architecture Plan

BSS Data Un-hardcoding & Dynamic API Integration Plan

This document details the exact plan to remove remaining hardcoded data on /worker, Contractor, and Employer pages, connecting them directly to Django REST backend APIs and Postgres database models.

1. Backend Enhancements (Django REST)

  • Enrich _worker_employment_section in v1_payloads.py: Update payload builder to return full contractor (code, LIN, contact, email), principal employer (code, LIN, industry, email), and site details (code, location, medical officer contact) from database models instead of partial strings.
  • Enrich _worker_compliance_section: Dynamically compute appointment letter status, active gate pass status, PPE records, and medical fitness days remaining.

2. Frontend Updates (Next.js / TypeScript)

  • TypeScript Interfaces (portal.ts): Expand WorkerEmployment and WorkerCompliance interface definitions to support detailed relational objects.
  • Worker Overview (/worker/page.tsx): Remove static siteInfo, contractorInfo, and employerInfo fallbacks and bind directly to worker.employment.
  • Compliance Page (/worker/Compliance): Bind Health & Safety, Access & Security, and Historical Records exclusively to live API data.
  • Contractor & Employer Portals: Synchronize Contractor worker lists (/contractor/workers) and Employer worker compliance oversight (/employer/workers) with backend payloads.
